# Deep Dive

サブクエスチョンの DAG を計画し、サブエージェントで並列に調べる自律型のディープリサーチ。外部 API には依存せず、エージェントの標準ツール（サブエージェント、Web 検索、タスク管理、ファイル書き込み）だけで完結する。

## 仕組み

1. **プランニング** — 質問を、依存関係を持つサブクエスチョンの DAG に分解する
2. **ファンアウト** — 互いに独立したサブクエスチョンを、サブエージェントで並列実行する
3. **ギャップ分析** — 各サブエージェントは調査結果と、判明したギャップを返す
4. **イテレーション** — ギャップを新しいサブクエスチョンとして DAG に戻す
5. **統合** — 全ノードが完了したら、最終レポートを作成する

## 手順

### 1. DAG に分解する

リサーチクエスチョンを受け取ったら、サブクエスチョンの DAG を生成する。各ノードは次のフィールドを持つ。

- **id**: 短い識別子（例: `q1`、`q2a`）
- **question**: 調査する具体的なサブクエスチョン
- **depends_on**: 先に回答が必要なノード ID のリスト（空なら依存なし）

**分解のルール:**

- 依存関係を持たない、基礎や前提知識を固める質問から始める
- 基礎的な回答に依存する、分析や比較の質問へと積み上げる
- ノード数は 4〜8 を目安にする。トピック上それ以上必要でも、上限は 12 とする
- 各ノードは 1〜3 回の Web 検索で回答できる粒度にする
- 他のコンテキストを持たない調査担当者でも回答できるほど、質問を具体的にする

**DAG をテーブルとして出力し**、ユーザーがプランを確認できるようにする。出力したら、確認を待たずにすぐ実行に移る。

**DAG の各ノードと、「ギャップ分析」「レポートの統合」をタスクとして作成する。** タスクの状態は、作業の開始時と完了時に更新する。ユーザーが進捗をリアルタイムに把握できるようにするためである。

```
| ID | Question | Depends on |
|----|----------|------------|
| q1 | ...      | —          |
| q2 | ...      | —          |
| q3 | ...      | q1         |
| q4 | ...      | q1, q2     |
```

### 2. 依存関係の順に実行する

DAG をトポロジカル順に処理する。

**ウェーブ 1:** 依存関係を持たないノードをすべて、**並列のサブエージェント**（Claude Code では Agent ツール）として起動する。各サブエージェントには次のプロンプトを渡す。

```
あなたは 1 つの質問に集中する調査担当者です。Web 検索を使って、次の質問 1 つだけに回答してください。

質問: [サブクエスチョン]

指示:
- Web 検索ツールを使い、最新で信頼できる情報を探す
- この質問は 1〜3 回の検索で答えられる粒度に分けてある。それで答えが得られなければ、検索を重ねずに Gaps に書く
- 具体的に書き、見つけた情報の出典を示す

回答は必ず次の形式で返してください。

## Findings
[具体的な事実、日付、数値を含む回答。出典は文中に示す。]

## Gaps
[完全には回答できなかった点、見つかった矛盾、回答を補強するための
追加の質問を列挙する。なければ「None.」と書く。]

## Sources
[各出典を「タイトル — URL」の形式で列挙する]
```

**出典の永続化:** 各ウェーブが完了したら、そのウェーブで得た出典をすべて、セッションの一時ディレクトリ（スクラッチパッドがあればそこ）の `deep-dive-sources-[topic-slug].jsonl` に追記する。形式は JSON Lines とし、1 行に `{"node_id", "title", "url"}` のオブジェクトを 1 つ書く。このファイルはコンテキストのコンパクションの影響を受けない。サブエージェントの結果がコンテキストから圧縮されて消えても、このファイルが出典の Single Source of Truth として残る。統合のステップでこのファイルを読み、最終レポートの Sources セクションを組み立てる。

**ウェーブ 2 以降:** ウェーブ 1 が完了したら、依存関係が解決したノードを起動する。サブエージェントのプロンプトには、依存先ノードの調査結果を含める。

```
あなたは 1 つの質問に集中する調査担当者です。Web 検索を使って、次の質問 1 つだけに回答してください。

質問: [サブクエスチョン]

これまでの調査で得たコンテキスト:
[依存先ノードの調査結果を貼り付ける]

[以降の指示は上と同じ]
```

全ノードが完了するまで繰り返す。

### 3. ギャップのイテレーション（最大 1 ラウンド）

全ノードが完了したら、すべてのサブエージェントから集めたギャップを見直す。

- ギャップが軽微で、最終的な回答に影響しない場合: スキップして統合に進む
- 結論を変えうる重大なギャップがある場合: 対象を絞ったサブクエスチョンを 1〜3 個新たに作り、最後の並列ウェーブとして実行する

### 4. 統合する

すべての調査結果を 1 つの最終レポートにまとめる。構成は次のとおり。

```markdown
## Deep Dive: [トピック]

### エグゼクティブサマリー
[要点となる結論を、ここだけ読めば判断できる長さで書く]

### 調査結果

#### [テーマ／セクション 1]
[関連するノードの調査結果を統合して書く。単にコピー＆ペーストしない]

#### [テーマ／セクション 2]
[...]

### 未解決の論点
[解決できなかった点。まだ不明な点を正直に書く]

### Sources
[全サブエージェントの出典を重複排除したリスト]
```

## ルール

- **必ず最初に DAG のプランを示す。** 出力したら、確認を待たずにすぐ調査を始める。
- **可能な限り並列化する。** 互いに独立した質問は、常に並行するサブエージェントで実行する。
- **ギャップのラウンドは最大 1 回。** 際限のない調査ループに陥らない。
- **連結ではなく統合する。** 最終レポートは、サブエージェントの出力を継ぎはぎしたリストではなく、一貫した 1 つのドキュメントとして読めるようにする。
- **確信度を正直に示す。** 調査で明確な答えが得られなかったら、そう書く。ギャップを推測で埋めない。
- **最終レポートは必ず永続化する。** 統合が終わったら、レポートを該当プロジェクトの `docs/deep-dive/` ディレクトリに Markdown ファイルとして保存する（ディレクトリがなければ作成する）。プロジェクトルートは、カレントディレクトリか調査依頼のコンテキストから判断する。ファイル名は日付とスラッグ化したトピック名にする（例: `2026-04-02-jira-docs-from-microservices.md`）。最終レポートを一時ディレクトリにだけ書いて終わらせない。必ず該当プロジェクト内の永続的な場所に保存する。
